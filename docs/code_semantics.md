# 3.13.4：代码语义来源、接续生成与可信重建

## 变更边界

本批修复离线语义资产流水线，不修改决斗网络、输入字段/形状、奖励、PPO/GAE、合法候选、Core 或 Link 协议。Model Protocol **4**、Checkpoint Format **3**、结构修订 **14**、静态语义格式 **1**、GKG 格式 **4** 均不变。新增代码生成清单格式 **1** 独立维护于 `code_semantic_provenance.py`；代码来源提取版本独立维护于 `lua_semantic_source.py`。

粗哈希与代码向量是两个独立渠道：原有 `_hash_code_block()` 继续规范化变量、布尔值和数值，以凸显泛化共通点；向量读取原始代码，保留真实参数/逻辑。本次不改粗分类规则，只清理重复/失效的接续索引成员。

## 已确认的根因

旧库共 27,647 条、384 维，只有 530 个逐位不同的向量，27,007 条完全相同。其中 26,942 条没有 `raw_code`，65 条为显式空源码；缓存编码器实际编码空字符串，与这组向量余弦相似度为 1（最大绝对误差约 2.22e-7）。这是缺源码仍生成空文本向量、接续只检查卡号/槽位存在而不检查内容共同造成的，不是粗哈希分类直接生成了相同向量。

旧提取还遗漏无 Condition/Cost/Target/Operation 的注册型效果和 SetValue 回调，并重复加入 Operation。原来的长代码编码受编码器上下文限制，尾部存在被截断风险。即使槽位和维度能校验通过，也不能证明生成来源正确。

## 新流水线

1. 词法扫描跳过注释，完整保留字符串；用块栈处理嵌套函数、if、循环、repeat，提取真实注册代码。效果槽顺序仍沿用既有 Lua 对象槽，不根据卡面描述或粗哈希重新编号。
2. 每槽包含顶层静态上下文、Effect 创建/注册、Clone 覆盖及引用回调闭包；SetValue、唯一可解析的本地/跨卡/utility/procedure 辅助函数纳入来源。公开 Core API 不复制其内部实现，代码不执行。
3. 保存 `code_source`：源码 SHA-256、代码块角色/名称/范围、依赖文件摘要、完整性和未解析引用。无法证明的动态引用/函数歧义保留注册代码并标为不完整，不制造“完整”或空代码回退。
4. 接续先核对来源版本、主脚本及依赖；缺来源旧卡或已改脚本重新提取。同卡号同槽位改代码也重生成向量；删除的效果不残留旧槽。完全不变的资产复用，不加载编码器。
5. 长代码按角色/函数边界分窗，窗口不超过编码器的 256 token，上下文重叠 32 token；角色、块序号、分块序号作为文本前缀。以新增 token 数加权均值再 L2 归一化为原来的 **384 维**，不增加每步输入。分窗覆盖尾部不是完整程序推理，也不是 MCTS。
6. `code_embeddings_meta.json` 记录实际编码器权重/配置/词表指纹、固定修订、分块策略、逐槽源码/编码摘要及 token/分块数、向量和索引文件摘要。tokenizer 的临时 padding/truncation 不计入编码器身份，避免一次编码后误触发重建。
7. 无清单旧向量可以作为旧模型原资产继续加载，但不得当成可认证接续向量；第一次本地更新全量重建。新版来源缺清单、文件摘要不匹配、源码变化未重生成均拒绝混用。

生成清单只证明内容和生成记录一致，不是签名认证，更不保证编码器准确理解 Lua。默认仍是原来的 `all-MiniLM-L6-v2` 通用句向量模型，没有更换为专门的代码模型或新增网络。

## 构建、检查与启用

CLI 保留现有 `parse` 操作，可指定独立输出目录：

```powershell
.\python_env\python.exe main.py parse --output semantic_builds/v3.13.4/knowledge_base.json --local-update
.\python_env\python.exe main.py semantic-check --directory semantic_builds/v3.13.4
```

`semantic-check` 为只读质量检查，不扫描 Lua、不下载、不生成向量，不产生运行日志文件。WebUI：**语义知识库引擎 → 代码语义质量**，只点击检查时运行，可切换资产目录；执行中枢和单卡/Hash 查看共用这个目录。目录改变不会自动切换训练资产，训练仍使用项目根目录资产。

此次可信重建保存在 `semantic_builds/v3.13.4/`，根目录旧知识库和向量未覆盖。`Galatea_Semantics_3.13.4.gkg` 是约87.32MiB、不含模型的资产包，已复制至 `deploy_packages/` 供WebUI直接选择；在 **模型部署与打包 → 解包与暂存库** 解包后精准导入，将整组源语义和编译运行表设为根目录资产。导入前保留原资产副本，停止训练/对局，导入后重新启动进程；不要在运行中替换资产。

**新向量改变 `semantic_lookup_hash`，不是改变网络协议。** 旧检查点与新语义资产混用会被既有身份校验拒绝；不做旧模型迁移，新 V4 训练从零开始。要运行旧模型，请使用其原始语义资产/独立旧包。重建目录被 `.gitignore` 排除，源码提交不会自动发布新资产；需按计划单独发布 GKG 或完整语义源组。

## 同步与打包

- 远程同步仍只下载，不自动本地生成。新版资产组必须包含知识库、向量、索引及生成清单，缺少清单不会把旧向量配给新源码；可随后本地提取重建。
- 保留源码的本地库可以内容感知接续；远程“清洁库”可以去掉 `raw_code`，但必须保留 `code_source` 摘要/代码块元数据和匹配的认证向量。缺源码只能复用同来源认证向量，不能重生成；需要本地 Lua 才能补齐。
- GKG 勾选“可接续语义源”时自动携带新版生成清单，与源码/向量/索引同组导入；旧无清单源组仍按旧资产边界校验。关闭源组时依然携带完整编译运行表，部署不需要 SentenceTransformer 或 Lua 扫描。
- 编译目录对生成清单另存文件摘要；来源文件发生变化时重新编译。模型的逻辑语义哈希仍由实际运行表/绑定计算，不把日志和生成状态当成输入。

## 结果与成本

本机全量重建：13,400 张有独立效果的卡、27,647 槽，全部源码非空；26,092 个逐位不同向量，最大相同组 657 条（旧库 27,007 条）。25,748 槽使用多个分块，合计 172,018 个分块。相同注册代码得到相同向量是允许的，不以“必须全部不同”作为质量标准。

27 槽存在未静态证明的辅助检查/引用，明确标记不完整；它们仍有注册和已知回调来源。可用质量检查和单卡查看定位，不追加人工效果标签。函数展开最多 128 个、单槽展开目标上限 128 KiB，文件索引 LRU 最多 256 个；达到展开上限也必须报告不完整。

长代码分块增加**离线首次构建**成本，源码/清单增大资产包和启动来源校验成本。知识库无损紧凑 JSON 保存由约104.71MiB降至73.70MiB，只移除排版空白，数据与逻辑身份不变。不扩大向量字典行数、模型参数或 rollout 单步存储，不在每步决策运行生成器。编译-only 部署可不带大源码组。无变化重跑验证已复用13,400张卡和全部27,647个向量，未加载编码器；编码器已加载时也确认全部复用。不能据此承诺棋力或学习效率提升，需后续新训练对照。
