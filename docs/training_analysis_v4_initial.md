# V4 首次云端训练分析记录

> 开发分析记录，适用于 2026-10-10 启动的单次 v3.14.0 / Model Protocol V4 实验。不是通用使用手册，也不是发布验收结果。
> [English](training_analysis_v4_initial_en.md)

本次记录核对训练内的胜率、预测误差、策略更新和耗时变化。结果支持训练分布内的进步与数值稳定，但不足以证明泛化能力或相对 V3 的严格加速倍数。通用图表定义见 [TensorBoard 指标手册](tensorboard_metrics.md)。

### 当前健康程度

**支持有效学习的证据：** RuleBot、历史对手和混合胜率均改善，Self 仍接近 0.5，而不是所有组同时异常趋近 1；Reward 从负转正、平均长度减少；未来资源预测损失下降；熵逐渐下降而非立即归零。规划逐维变化仍存在、活跃维比例一直为 1，策略/价值门逐步开启，未见明显常数塌缩或门饱和。78 轮 PPO 的 Nonfinite_Batches 全为零，所读取固定标量也没有 NaN/Inf。

**仍需观察，而不是判为全绿：**

1. 第 4 轮起直到第 78 轮每轮 KL 停止，共 **75/78 次**。有效 epoch 后期约 1.6，仍有真实学习，不是零更新；但说明上限 4 多数没有用满。KL_Max 全程最高约 **0.0803**，51～76 轮的均值约 0.0381。触发批不更新不等于已完成的策略偏移一定很小，需结合固定基准和继续训练走势，不建议仅为“完成四次”关闭保护。
2. Value_Loss 窗口均值从 0.0070 增至 0.0170；Explained_Variance 仍约 0.90，暂不像数值崩坏。目标回报/对手分布在变化，绝对误差可能增加，但不能说价值学习一直变好。
3. 辅助终局准确率在 11～30/51～76 轮分别约 90.7%/89.6%，规划终局准确率约 91.8%/90.5%；规划 Total_Loss 也不是单调下降。终局判断仍需继续训练与独立评估，不能只摘取截图末点 95% 来宣布完成。
4. 76 轮 Reward 原始值是 **0.0744**，明显低于其显示平滑值约 0.1837；77、78 轮又为约 0.330/0.193，第 79 轮采集约 0.073。说明确有轮间波动，当前不能仅由一个低点判退化，也不能忽略它。
5. cancel_rate 后期上升、state_changed_rate 非单调；取消可能是合理策略，也可能有未充分改善的循环。结合全息回放中的完整选择流程看，不凭比例单独定性。微小 retry_rate 和零 Deadlock_Rate 的范围限制见前文。

### 采集效率的明确边界

当前采集基本碰到 **600 秒预算**，约 606 秒还包含启动、结束与合并等开销。Worker 会在预算前留余量并截断正在进行的局；Trainer 还有等待/终止保护。这不是 PPO 更新要花 600 秒，也不是 TensorBoard 的 timeout_rate 本身就能完整还原时间预算截断。

用采集秒数×有效行/秒还原，**已完成 PPO 的前 78 轮约提交 225.23 万有效采集行，平均 28875 行/轮，只有目标 32768 的约 88.1%**；第 79 轮另已采集约 26970 行。这里未累计 epoch 复用，但各行并非统计独立的对局样本；计算从事件文件的 float32 标量还原，取整数近似。78 次更新共完成 **7831 次 mini-batch 优化器更新**，约 400.95 万次样本使用，包含跨 epoch 复用。

PPO 耗时下降大部分与有效复用次数减少相符，不能全归功于运算优化。后段采集吞吐还从前段约 48.6 降到约 46.9 行/秒，幅度不大但不是持续加速。当前主要时间预算在采集，不建议未定位环境/历史对手/中央推理耗时前重构训练器。若后续调整 timeout，要当作改变采集分布与预算的对照，不是保证棋力提升的按钮。

## 2. 学习速度改善的可能原因

下面是与实现一致的**机制解释与待验证归因**，不是此次单一 run 已证明的因果拆分。V3 的“近千轮高度”来自历史对局观察，本次没有完整匹配 V3 的事件文件、对手/卡组/资产/预算，不能据此计算严格加速倍数。

### 2.1 输入从“必须猜”变成“直接区分”

V4 精确词表消除旧 modulo 卡片 ID 混淆；Main/Extra 分区、阶段/区域/表示类别、决策玩家与回合玩家解耦、动作操作族与召唤/选择/公开关系信息，使不同策略情形不再被错误合并。网络容量相同并不意味着可辨别信息相同。

如果两个局面或候选在输入上难以区分，增加训练也只能对混在一起的目标折中。改进输入可使同样大小的网络更容易学到“现在应该发动而非盖放”“这是攻击还是结束阶段”“这张卡属于额外终端”的条件关系。它不会自动赋予最优规则，但减少了表示歧义与从结果反推缺失字段的负担。对应 [精确身份与玩家状态](protocol_v4_implementation.md#3-目标数据协议)。

### 2.2 语义资产修复可能是很大的贡献，但与 V4 架构加成不同

旧代码向量库审计发现 27647 槽只有 530 个逐位不同向量，其中 27007 个相同，多数实际来自空源码编码。重建后为 26092 个不同向量，保留真实注册、回调与长代码尾部，见 [代码语义来源修复](code_semantics.md#已确认的根因)。

**如果 V3 那次训练使用了这组旧资产**，大量效果的代码语义渠道实质提供近乎相同的信息；新资产使已有语义模块终于能利用更真实的差异，这可能比仅多几个网络分支更重要。它是很有根据的候选原因，但不证明通用编码器已经理解全部 Lua，更不能把全部增益归给 planner。旧模型必须用旧配套资产运行，不做“换库后对比”以免破坏身份/输入。

### 2.3 卡组风格与 FiLM 提供了条件，而不是额外规则奖励

稳定 Main/Extra 画像通过 Deck Encoder 形成学习型风格 latent；分层 FiLM 将卡组风格与阶段、身份/时局分开调制。相同手牌/场面动作在不同卡组终端和时局下可以获得不同评价，使网络不必用一套无条件倾向处理全部卡组。

这是从整体构成到局内策略的可学习条件化，不是人工把卡组固定分成进攻/防守类别。是否有助于未见构筑，需要卡组家族隔离测试；条件化本身也可能学会训练环境的偏好。对应 [Deck Encoder](protocol_v4_implementation.md#41-可复用-deck-encoder)、[分层 FiLM](protocol_v4_implementation.md#42-分层-film)。

### 2.4 辅助监督让每步动作都有更近、更具体的学习信号

原来终局奖赏要经价值/优势把胜负归因到较远动作。现在一次实际动作还可监督“产生什么公开事件、LP/资源如何变、连锁末/回合末如何结束、真实终局是什么”。即便外部奖励仍主要来自胜负，共享表示也不必只靠稀疏胜负发现全部有用特征。

普通辅助头不回填动作概率、不替模型执行规则；它通过小权重与受控梯度帮助共享表示提取对实际后果有用的信息。截图与原始记录的未来 Loss 下降支持这些预测在学习，但不能独立证明它们贡献了多少胜率。辅助任务改善共享表示/样本效率有研究依据，本项目任务与实现并不等同于该论文，也不能移用其加速数字，见 [UNREAL 原论文](https://arxiv.org/abs/1611.05397)。

### 2.5 规划表示把未来摘要接回策略，但还不是搜索

planner 不输入真实未来，而从当前状态/卡组/时局生成可被多尺度未来目标监督的摘要，再由逐渐开放的有界残差接回策略和值。相比只能从独立瞬时候选分数中隐含学习长线关系，它有显式训练压力去组织“这个局面未来会形成什么资源/结果”。

一致性约束避免同阶段小变化就完全重置表示，但不规定具体连续动作。它可能帮助 combo 的目标/过程关系更容易被共享，当前不能从 latent 的钟形分布直接证明已学会某条连段。对应 [规划实施规格](protocol_v4_implementation.md#45-目标与过程表示)。

### 2.6 实际还有 GAE 变化：不是“除 KL 外全是认知优化”

本次文本确认 lambda=0.98，旧默认为 0.95。在 gamma=0.998 时，GAE 对更远 TD 残差的递推权重是 `(gamma×lambda)^距离`：

| 条件 | gamma×lambda | 权重几何和 1/(1−gamma×lambda) | 100 步后残差权重 |
|---|---:|---:|---:|
| lambda=0.95 | 0.94810 | 19.27 | 0.00485 |
| lambda=0.98 | 0.97804 | 45.54 | 0.10856 |

所以更远 TD 信号在当前更新中衰减慢一些，有可能利于多段展开的信用分配。**这些数是 GAE 残差权重，不是模型只记 19/46 步、也不是终局奖励必定完整传播 100 步**；价值 bootstrap 和反复训练仍起作用。较高 lambda 同时提高长距离估计的方差，并非越大越好。若旧训练手动用过别的 lambda，必须按实际配置重算。原理见 [GAE 原论文](https://arxiv.org/abs/1506.02438)，本项目变更见 [3.13.0 更新记录](changelog.md#v3130---2026-10-01)。

### 2.7 KL 保护与数据反馈可能让进步更容易保留

KL 不增加认知信息，也不把差动作变成好动作；它减少在同一批旧策略样本上反复更新到过大偏移的风险，使已有改善更可能保留。这是合理机制，不是已证明旧 V3 全部被过大更新拖累。

若真实对局更短，同一交互预算可提供更多已完成终局和可用未来标签，又促进特征学习；当前长度下降、终局覆盖较高与此方向一致。但 Worker 均值和截断口径有偏差，需逐局统计才能证明更多终局的数量。CUDA 语义聚合优化则保持学习输入/目标不变，主要修大块临时分配，不应被解释成新增认知。
