## 一键包启动

### Windows 用户

直接双击 `一键包启动Webui.bat` 即可。启动器会先检查并修复依赖，再打开
`http://127.0.0.1:8501`。

![一键包启动窗口](图片/一键包启动窗口.png)

> 💡 如果没有自动打开浏览器，请手动访问 `http://127.0.0.1:8501`

### Linux 用户

Linux 用户请参考 [README.md](../README.md#linux-用户) 中的自动化安装教程，使用 `setup.sh` 一键配置环境，或手动使用requirements.txt安装完整环境


## 同步资源与卡库

点击侧边栏进入 **🔄 资源同步中枢**：

1. 勾选 **🃏 更新 CDB卡库与官方 Lua 脚本**
2. 点击 **🚀 立即开始同步**

![资源同步](图片/资源同步.png)

等待几分钟同步完成。这会从官方仓库拉取最新的 `cards.cdb` 和 `script/` 目录，确保 AI 掌握最新规则。

## 构建语义知识库

点击侧边栏进入 **🧠 语义知识库引擎**：

1. ⚠️ **重要**：勾选 **🌐 从 Github 拉取基础卡库同步**（首次使用必须勾选，可大幅加速解析）
2. 点击 **🧠 开始提取卡片语义**

![语义知识库](图片/语义知识库.png)

> 📖 语义化模块的工作原理和 Hash 聚类算法详见 [特殊处理逻辑 - 语义化模块](special_handling.md#语义化模块semantic-kb)

等待解析完成（首次可能需要几分钟），之后的知识库会被保存到 `knowledge_base.json`。

## 准备卡组

有多种方式获取卡组：

### 方式一：使用一键包自带的测试卡组

一键包内通常会附带几个 `.ydk` 测试卡组，可直接使用。

### 方式二：手动上传

点击侧边栏进入 **🗃️ 资产与卡组管理 → 📂 卡组与环境管理**：
- 将你的 `.ydk` 文件拖入上传区
- 可建立子文件夹分类管理（如 `tier1_meta`、`fun_decks`）

### 方式三：在线爬取（推荐）

点击侧边栏进入 **🗃️ 资产与卡组管理 → 🌐 在线动态环境构建**：
- 选择目标标签（如 `🏆 TCG 比赛上位`、`⚔️ 竞技天梯` 等）
- 设置抓取数量
- 点击抓取，自动批量下载卡组

![在线爬取卡组](图片/在线爬取卡组.png)

## 调整卡组权重（可选）

点击侧边栏进入 **🗃️ 资产与卡组管理 → ⚖️ 动态环境权重调度**：

- 为每个环境池设置权重（0.0 ~ 10.0）
- 权重越高，AI 越常在该环境中训练
- 可随时动态调整，Worker 下局即生效

![权重调整界面](图片/权重调整界面.png)

> 📖 权重调整和虚拟伪装池的详细说明见 [特殊处理逻辑 - 卡组权重调整](special_handling.md#卡组权重调整global-weights)

## RuleBot 环境压测（可选）

点击侧边栏进入 **⚔️ 启动与监控中枢 → 🛠️ 规则自检压测**：

- 设置压测局数（建议 50-100 局）
- 点击启动，检验引擎和脚本稳定性
- 建议在首次训练前运行一次，确保环境无问题

## 启动训练

点击侧边栏进入 **⚔️ 启动与监控中枢 → 🔥 发起训练 (Train)**。

### 参数分类概览

Galatea-Core 的训练参数分为三个层级，理解这个分类有助于你更好地调参：

| 层级 | 包含参数 | 特点 |
|------|----------|------|
| 🧠 **大脑结构** | `d_model`, `n_heads`, `n_layers` | 相当于 AI 的脑容量——定义后不能中途修改（模型架构已定型） |
| ⚙️ **训练配置** | `batch_size`, `mini_batch`, `workers`, `timeout`, `device`, `no_compile`, 以及下方 RL 超参数 | 可以在接续训练时随时调整 |
| 🗂️ **环境配置** | 卡组权重、虚拟池、泛用卡池 | 完全与训练模块解耦，可以在训练中实时调整 |

> ℹ️ 恢复训练时，大脑结构参数会自动锁定为存档中的配置。训练配置和环境配置均可自由修改。

> 🔐 新训练会自动生成只读 UUID；恢复训练继承原 UUID、模型前缀和内置轮次。文件名仅用于
> 展示，恢复进度以内置轮次为准。检查点协议版本不一致时，WebUI 会先告警并拒绝直接恢复。

### 参数简表

| 参数 | 说明 | 新手推荐值 | 内存/显存影响 |
|------|------|------------|---------------|
| **存档加载器** | 选 "None" 从头训练 | None | - |
| **模型前缀** | 新模型输出文件前缀；恢复时自动继承 | galatea | - |
| **d_model** | 🧠 特征维度（越大容量越高） | 256 | ⬆️ 内存/显存 |
| **n_heads** | 🧠 注意力头数 | 4 | ⬆️ 内存/显存 |
| **n_layers** | 🧠 Transformer 层数 | 2 | ⬆️ 内存/显存 |
| **轮次模式** | 训练到绝对轮次，或从存档追加轮数 | 追加 1000 | - |
| **总经验池** | 每次采集步数 | 4096 | ⬆️ 内存（主要） |
| **切片大小** | PPO 单次训练批量 | 256-512 | CUDA 模式占显存；CPU 模式占内存 |
| **进程数** | 并行进程数 | 4（按CPU核数） | ⬆️ 内存（主要） |
| **timeout** | Worker 单次采集超时 | 300s | - |
| **训练设备** | auto / cpu / cuda | auto | 决定中央推理与 PPO 的设备 |
| **导出 ONNX** | 保存点同步导出历史对手引擎 | 按需开启 | 占用额外存储 |
| **禁用编译** | Windows 建议开启 | 开启 | - |

> 💡 **内存/显存调优口诀**：`batch_size` 和 `workers` 主要占内存；CUDA 模式下 `mini_batch` 主要占显存。内存不足优先降低 workers，显存不足优先降低 mini_batch 或改用 `device=cpu`。中央批量推理固定启用，Worker 数量不要超过 CPU 物理核心数。

### 推荐配置方案

#### 🧪 新手测试（快速验证）

| 参数 | 值 |
|------|-----|
| d_model | 128 |
| n_layers | 2 |
| 目标轮数 | 100 |
| 总经验池 | 2048 |
| 切片大小 | 128 |
| 进程数 | 2 |
| 训练设备 | cpu 或 auto |
| timeout | 300 |

#### 🏆 正式训练（追求实力）

| 参数 | 值 |
|------|-----|
| d_model | 512 |
| n_layers | 6 |
| 目标轮数 | 5000+ |
| 总经验池 | 16384 |
| 切片大小 | 256 |
| 进程数 | 6-8 |
| 训练设备 | auto（优先 CUDA） |
| timeout | 600 |

配置完毕后，点击 **🔥 在后台启动训练**。

![启动与监控中枢](图片/启动与监控中枢.png)

## 查看训练成果

### 实时日志

训练启动后，在 **⚔️ 启动与监控中枢** 底部可看到实时终端日志和异常警报。

### TensorBoard 曲线

点击侧边栏进入 **📉 训练流形图**，点击 **🚀 启动 TensorBoard** 查看训练曲线：

| 关键指标 | 理想趋势 |
|----------|----------|
| `Train/Total_Loss` | 逐渐下降 |
| `Train/Entropy` | 缓慢下降 |
| `Rollout/Average_Reward` | 逐渐上升 |
| `League_Overall/WinRate_Total` | 逐渐上升 |

### 卡组生态大盘

点击侧边栏进入 **📈 卡组生态大盘**，查看各卡组的胜率统计和克制矩阵。

## 竞技场测试模型

训练完成后，点击 **⚔️ 启动与监控中枢 → 🏟️ 发起竞技 (Duel)**：

1. **出战模型 (P0)**：选择你训练好的 `.pth` 模型
2. **守擂模型 (P1)**：选 "None" 对战 RuleBot
3. 设置对战局数和读心频率
4. 点击 **⚔️ 在后台启动竞技场**

测试结果可在 **📈 卡组生态大盘** 中查看，AI 决策过程可在 **👁️ 全息读心回放** 中回放复盘。

![全息回放](图片/全息回放.png)

## [备用路线] 使用打包包体启动

如果你获取的是他人打包好的 `.gkg` 训练成果包，可以跳过训练直接体验：

1. 进入 **📦 模型部署与打包 → 📤 解包与选择性导入**
2. 将 `.gkg` 包放入本地仓库文件夹
3. 选择解包后，勾选需要导入的模型和知识库文件
4. 点击导入

导入完成后，模型会出现在 `./models/` 目录中，直接转到上方 [竞技场测试模型](#竞技场测试模型) 或 [全息读心回放](#查看训练成果)。
