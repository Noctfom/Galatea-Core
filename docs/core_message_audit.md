# 3.13.2：固定 Core 报文与认知缺口审计

本文件区分“知道消息长度”“正确维护状态”“进入模型观测”三个层次。能拆开原始消息，
不等于模型已经理解消息；规范轨迹保留原始字节，也不等于它们已经参与训练。

范围：随包公开 Fluorohydride 旧式 Core ABI。没有修改 Core 源码或二进制。
框架 3.13.2；Model Protocol 4 / Checkpoint Format 3 / 网络结构修订 13 不变。
独立原始轨迹格式为 2，全息 JSON 格式仍为 3。

## 已实施：16、31、21

### Type 16：SELECT_CHAIN

负载按小端排列：

```
player:u8, count:u8, special_count:u8, hint_timing:u32, opponent_hint_timing:u32
重复 count 次：effect_mode:u8, forced:u8, code:u32, location:u32, desc:u32
```

负载长 `11 + 14×count`，含消息类型的总长 `12 + 14×count`。
`effect_mode` 为普通动作 0、操作提示 1、重置提示 2；强制标志是每项独立的 `forced`。
Core 仅在没有任何强制候选时接受 `-1`，并非根据时机字段决定是否可取消。

旧解析错把第一个时机字节当全局 forced，第一个候选的 forced 当 mode，后续 mode 当
“分隔符”。有候选时总长碰巧一致，卡密/位置/desc 通常仍对齐，但时机、标志和取消合法性错误；
空候选则错误期待多一个字节，造成未消费消息。现由 `core_message_protocol.py` 共用严格解码，
模型和 RuleBot 使用相同取消条件。报文截断/非法字段显式失败，不静默选择默认动作。

空候选只自动应答 `-1`：不采样、不消耗 RNG、不请求中央推理、不新增 PPO 样本、
模型决策步数或动作转移事件。Worker、竞技场和 RuleBot 自检统一处理。
轨迹的 `automatic_response` 单独保存/校验/重放，不能成为行为克隆动作标签。

### Type 31：CONFIRM_CARDS

```
player:u8, skip_panel:u8, count:u8
重复 count 次：code:u32, controller:u8, location:u8, sequence:u8
```

`skip_panel` 是是否跳过展示面板，不是未知字节；两种值均正确消费并公开同一确认列表。
共享解码保留完整位置字段，现有状态路径继续将确认卡密交给记牌逻辑，不因此公开其他隐藏卡。

删除 CLI `--standard_core`、三处 WebUI 控件、Trainer/Worker/Arena/DuelManager 参数及全局
`CORE_HAS_GHOST_BYTE`。本项目只维护随包布局；未来更新 Core 必须进行独立迁移审计，不能靠开关猜布局。

### Type 21：SORT_CHAIN

这是对给定候选进行排序的交互，不是新增效果或发动连锁。此前私有候选解析/宏排序/响应
包装已存在，但 `DuelState.update()` 的交互分发遗漏 21，完整路径可能沿用旧候选。
本批补齐分发，验证玩家身份、候选和排序字节。当前随包 Core 常见执行路径不发此消息，
因此真实对局覆盖以现有消息为主；21 通过公开格式构造报文验证。

## 待用户确认：120、160、165（本批没有补全认知）

### Type 120：MISSED_EFFECT，错过发动时点

字段为 `location:u32, code:u32`。Core 在可选触发效果不具备 DELAY 等条件、相应时点
被后续处理跨过时通知客户端。它不是“已经发动的效果被无效”，不是玩家选择 Cancel，
也不是所有“不允许发动”的统一通知，更不代表对局非法。

当前：长度识别正确，但 `DuelState` 没有对应事件状态，公开转移事件白名单/结果位没有 120，
Encoder 也没有专门输入。原始轨迹会保存它，但模型无法从现有观测直接辨别“刚才这个效果错过时点”。
后续场面/胜负仍可能间接提供学习信号，不等于完全无法学习相应操作。

建议：增加可见“错过发动时点”事件，包含来源玩家、位置、卡密和结果标志，经既有事件历史
进入模型，并在回放中显示。**不新增人工扣分**。消息不含效果 desc/槽位、错过原因编号，
不能据此精确宣称某个 Lua 效果槽或某个先前动作一定有错；存在歧义时保留未知。

### Type 160：CARD_HINT，卡片实例提示

字段为 `location:u32, hint_type:u8, value:u32`；绑定的是该位置的卡片实例，不是整类同名卡。

| hint_type | 完整含义 | 不能混同的内容 |
| --- | --- | --- |
| 1 / TURN | 卡片回合计数提示 | 不是 101/102 的实际指示物增减 |
| 2 / CARD | 关联/宣言的卡片密码提示 | 不修改该卡自身身份 |
| 3 / RACE | 宣言种族提示 | 不等同卡片当前实际种族 |
| 4 / ATTRIBUTE | 宣言属性提示 | 不等同当前实际属性 |
| 5 / NUMBER | 数字提示 | 不自动等同攻击力、费用或指示物 |
| 6 / DESC_ADD | 添加效果说明提示 | 按 desc 计引用数，不是简单布尔开关 |
| 7 / DESC_REMOVE | 撤销一份说明提示 | 还有相同提示的其他来源时不能全部删除 |

当前：拆包知道 9 字节，但没有实例提示状态表、转移事件编码或模型输入。
即使查询已覆盖实际攻防、无效/禁止标志、正规出场状态等，也不能还原宣言值或客户端说明。
Lua 静态语义说明“卡可能做什么”，无法代替“这一实例目前被提示了什么”。

建议：数值提示与说明提示分开存储；后者按实例和 desc 维护引用数。严格跟随 Core 的添加/
撤销以及移动、重建、洗牌刷新生命周期，不能把动态 location 当永恒实例 ID。客户端可能
先重建实体再重发提示，需先清旧映射，避免重复累加。只用 Lua 精确映射或原始 desc 身份，
不再用 `desc & 15` 猜槽位。无法解释的提示保持未知，不制造人工效果分类或自定持续时长。

### Type 165：PLAYER_HINT，玩家级说明提示

字段为 `player:u8, hint_type:u8, desc:u32`。当前随包 Core 的核心含义是 6 添加/7 撤销：
为受影响玩家显示持续说明。它不绑定场上的某个槽位，来源离场后提示仍可能存在。
公开客户端对部分特殊说明还会控制区域查看权限，不能一概当纯装饰文字。

当前：拆包知道 6 字节，没有玩家提示状态表、事件编码或模型输入。
建议按玩家+desc 维护引用计数，以 Core 的添加/撤销决定生命周期；通过有界结构化观测提供
给策略/价值网络，Side 不进入此路径。回放应能显示提示建立和撤销。

**重要边界：160/165 不等于通用“已生效效果追踪器”。** Core 只有在脚本/效果要求客户端
提示时才报告这些信息，未标记 `EFFECT_FLAG_CLIENT_HINT` 的效果不会因此完整公开。
本地 `script/c23434538.lua`（增殖的 G）注册的抽卡持续效果没有该标志；
`script/c94145021.lua`（小丑与锁鸟）相关效果也没有。因此即使补齐 165，也不能承诺完整记录
这两张卡的持续影响。只能利用已有公开事件推断，或将精确覆盖问题另行立项；本批不做猜测式追踪。

三项建议都属于后续模型输入/事件协议实现，不只是加几行回放文字。需要同步
Encoder、存储/共享内存、训练和 ONNX/Link 边界后再实施；不能只在竞技场接入。

## 已确认暂缓：35；待用户确认：37/38、162（本批保持原行为）

### Type 35：SWAP_GRAVE_DECK，墓地与卡组交换

负载只有 `player:u8`。交换整片区域，不是双方互换，也不是将墓地洗回卡组那么简单。
Core 把该玩家原卡组送入墓地、原墓地变为卡组；墓地内融合/同调/超量/连接等额外怪兽
会分流回额外卡组，再做顺序、状态重置和洗牌。原卡组里侧/额外中卡片不能被框架提前公开。

当前缺口：无批量交换状态分支；后续查询可刷新墓地等实体，但未查询的卡组/额外剩余列表
和记牌映射可能陈旧，无法靠普通单卡 MOVE 全部修复。稳定构筑 DeckProfile 应保持不变。
2026-10-09 用户确认：暂不适配此少见的批量区域交换，保留上述已知缺口。
“现世与冥界的逆转”是相关卡例，不代表只有该卡能使用这项 Core 操作；当前不能承诺
此类对局的卡组/额外剩余认知和记牌映射完整正确。本次决定不修改 Core 或训练行为。

若日后支持，需按真实分流处理批量区域变化、数量和可见性，重建/清理相关实例标签，再查询核验；
不能直接交换两个 Python 列表后就宣称完成。

### Type 37：REVERSE_DECK；Type 38：DECK_TOP

37 无负载，通知全局“卡组反转状态”切换；不是只反转当前行动玩家。
38 为 `player:u8, offset:u8, code:u32`，更新从顶端偏移处的已知卡。
`code` 高位 `0x80000000` 是该卡在卡组中的表侧标志，应与实际卡密分离。
37 本身不包含全部顺序，38 也不是整副卡组公开，不可以凭这两项还原隐藏排序。

当前缺口：无反转标志或公开顶部位置状态；构筑集合认知不提供下一抽顺序。
建议维护反转状态和有界“已公开顶部卡”映射，跟随洗牌、抽卡、移动等作失效/平移，
不可把过期顶部身份继续当作下一抽。规则少见，但启用后是实质观测缺口。

### Type 162：RELOAD_FIELD，场面重建快照

内容包括规则号、双方 LP、7 个怪兽槽/8 个魔陷槽的占用和表示、叠放素材数量、卡组/
手牌/墓地/除外/额外数量、表侧额外数量，以及当前连锁的卡密/位置/发动方/desc。
它**不是完整卡片查询**，没有全体卡密/攻防/所有持续效果；恢复完整观测仍需配套公开查询。
主要服务场面重载/调试预置等边界，不能断言每个 Link 客户端重连都会发它。

当前有两个缺口：变长长度解析按 `rule < 4` 只读 5 怪兽槽，但随包 Core 固定写 7 槽；
`DuelState.update()` 也没有快照重建分支。现代普通完整开局较少触发，若承诺读取中途快照/
自定义预置，就属于必须修正的适配边界。建议统一 7/8 布局、原子替换快照、清理无法继承
的历史实例状态并配套公开查询；从中途开始的轨迹不伪造完整起局历史。

## 影响与验证边界

- 本批修正会改变此前错判取消合法性时的候选池和时机特征；这是纠错，不承诺错误旧路径逐位相同。
- 不改 PPO/GAE、奖励、网络参数、ONNX 输入输出形状或额外效果追踪；空提示不新增学习样本。
- 解码工作量与候选数线性相关；没有新增后台线程、推理调用或常驻大表。轨迹开启时会多存
  已实际处理的空消息/自动应答，小量 I/O 增加不等于零成本，也不宣称完整长训提速。
- 校验覆盖构造边界/截断报文、完整 Type 21 分发、真实 Core 模型对局、录制开关对照、
  原始响应/观测摘要重放及 WebUI 控件。小配置冒烟不能替代生产规模长训。
- 曲线统一叫“AI 预测”：表示模型理解，不代表实际胜率。仅修改界面说明，不改变概率或训练目标。
