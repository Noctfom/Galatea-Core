## [v3.6.3] - 2026-09-05

### 🛡️ V3 审计收口与 PPO 可观测性

- **审计改为显式诊断开关**：训练和竞技场默认不再逐进程采集 V3 报告；CLI 新增 `--protocol-audit`，WebUI 训练/竞技场表单同步提供开关。RuleBot 自检仍默认开启，方便专门协议压测
- **审计日志纳入仓库管理**：“存储与日志仓库”新增 V3 审计报告标签页，支持 JSON 预览、下载、批量删除和二次确认清空
- **修正区域序号假阳性**：审计不再把卡组、手牌、墓地、除外区和额外卡组中大于 31 的合法顺序误报为异常；怪兽区和魔陷区继续按固定槽位边界校验
- **修复审计表 Arrow 展示报错**：WebUI 的“Lua 绑定语义槽”统一为显示字符串，已绑定整数与未绑定占位符不再触发 PyArrow 混合类型异常
- **补全 PPO 健康指标**：TensorBoard 新增 `Approx_KL`、`Clip_Fraction`、`Explained_Variance` 和裁剪前 `Gradient_Norm`；指标只在原有每 20 个 mini-batch 日志频率上基于现有张量计算，不参与损失或反向传播
- **补全吞吐耗时指标**：每轮记录采集秒数、PPO 更新秒数和有效样本/秒，可在 TensorBoard `Performance/` 分组中直接区分环境、历史对手与梯度更新耗时
- **协议与存档保持不变**：不修改网络输入、奖励、动作、PPO 损失或梯度更新；Model Protocol 保持 3，Checkpoint Format 保持 2，现有 V3 检查点可直接恢复
- **稳定版回归**：通过 151 项自动化测试，1 项需显式启用真实 Core 的长局测试按预期跳过

## [v3.6.2] - 2026-09-04

### 🔗 Lua 运行时效果与代码语义精确绑定

- **移除错误的低位假设**：Core `desc` 的低四位只保留 Stringid 索引，不再被当作 `Effect.CreateEffect(c)` 的创建顺序；框架不会再因此写错 `used_effect_mask` 或把连锁聚焦到错误语义槽
- **基于 Lua 对象身份生成映射**：语义解析时跟踪每个顶层 Lua Effect 对象及其静态 `SetDescription(aux.Stringid(...))`，把完整运行时 `desc` 写入同一代码语义槽；不读取也不解析卡面描述文本
- **歧义安全回退**：动态表达式、无描述被动效果和多个 Effect 对象共用同一 `desc` 的情况不做猜测；候选、连锁与历史继续使用整卡语义，且不会错误标记某个效果已发动
- **候选动作获得精确效果语义**：合法动作新增紧凑 `act_effect_slot` 输入；存在实体指针与精确绑定时，策略头直接索引该槽的现有 Lua 代码向量。实现采用展平索引，只生成候选数量级的选中向量，不展开候选×8槽大张量，也不增加网络参数
- **统一运行时链路**：GameState、动作候选、12 项连锁、8 项发动历史和实体已用效果位共用同一映射；连锁/历史只在精确绑定时收窄到单槽，未知绑定保留原整卡注意力掩码
- **语义资产与审计升级**：资产启动校验新增运行时绑定的一对一、类型和范围检查；WebUI 不再显示“V3 假定槽”，而是显示 Lua 实际绑定槽与 `binding_missing` 安全回退；审计报告格式升至 2
- **现有资产迁移**：当前 27,647 个代码语义槽与向量索引保持不变；新增 13,831 个精确运行时绑定，覆盖 8,951 张卡。检测到 94 个由多个 Lua 对象共用的歧义标识，均按设计未写入映射
- **相邻问题修复**：语义缓存构建改为尊重知识库显式 `slot` 字段，不再隐式依赖 JSON 列表顺序；协议仍为 Model Protocol V3，检查点与部署包容器格式保持 2，但 ONNX 应按本版输入重新导出
- **CUDA 编译安全回退**：训练启动前确认 CUDA Inductor 的 Triton 后端可用；一键环境未安装 Triton 时不再等到首次前向才延迟崩溃，而是明确提示并使用结果等价的 eager 路径
- **完整回归**：149 项自动化测试通过（1 项按环境跳过），包括精确/跨卡/歧义绑定、错误资产拒绝、PyTorch 前向、ONNX 导出及 ONNX Runtime 推理；另通过 1 局真实 Core 模型对 RuleBot 冒烟测试

## [v3.6.0] - 2026-09-03

### 🧠 顺序上下文与模型协议 V3

- **修复连锁/历史顺序聚合失效**：旧结构先给序列加位置向量再直接求均值，交换 A→B 与 B→A 后总和不变。新 `OrderedContextPool` 先绑定位置，以非对称局部卷积建模相邻关系，再通过掩码注意力汇聚，连锁 12 槽和最近发动历史 8 槽现在能产生不同的顺序表示
- **严格处理填充和空序列**：填充槽在局部混合前后均被遮蔽，即使含异常值也不会污染上下文；没有有效项时稳定返回有限零向量
- **绑定效果槽身份**：8 个 Lua 效果槽新增显式槽位嵌入，使实体的 `used_effect_mask` 第 N 位能够和第 N 个效果语义对应，不再把同卡多效果视为可任意交换的集合
- **补全当前连锁认知**：每个连锁项除卡片语义外，新增卡号、效果描述、链序、处理卡位置、触发位置和双方相对控制者；这些公开信息按行动方视角编码后再进入顺序聚合
- **模型协议升至 V3**：连锁输入张量和网络结构已经扩展，PPO 公式保持不变；旧模型权重不再结构兼容，因此 `MODEL_PROTOCOL_VERSION` 从 2 升至 3，检查点容器格式仍保持 2
- 默认 512×6 网络中，顺序聚合、效果槽身份和连锁元数据投影合计新增 681,984 个参数，约占当前模型 1.37%；顺序聚合支路的本机 batch 512 前向微基准约为 CPU 14.5 ms / CUDA BF16 1.0 ms，不改变 Worker、中央推理或 ONNX 调用流程

### 🧬 可接续语义资产

- **修复 Lua 语义非确定性**：字段去重从无序 `set` 改为保留首次出现顺序，避免固定槽位截断时因 Python Hash 随机盐保留不同语义；脚本扫描也改为稳定文件顺序
- **完整 GitHub 语义同步**：`--sync` 现在同步知识库、Hash 映射、代码语义向量与向量索引，解析本地新增脚本后自动接续生成缺失向量；远程缺少 Hash 映射时可从知识库中的自定义标签重建接续索引，无新增槽位时不会加载向量模型
- **代码语义增量生成**：`--embed` 在现有向量与索引一致时只计算新增效果槽；`--clear` 会同步清除旧向量，维度、行数或索引不一致时自动安全全量重建
- **部署包格式 V2**：WebUI、CLI 与 `.gkg` 安全清单支持 `hash_mapping_report.json`、`code_embeddings.npy` 和 `code_embeddings_idx.json`，向量与索引必须成对并与知识库一并打包；一键包发布预检也要求完整语义资产
- **完整回归**：138 项自动化测试完成（1 项按环境跳过）；顺序交换、效果槽身份、连锁报文/视角编码、增量向量、语义包回读、完整 PyTorch 前向、`torch.compile`、ONNX 导出及 ONNX Runtime 推理均通过

## [v3.5.1] - 2026-09-02

### 🎞️ 全息回放 V2

- **改为双边完整时间轴**：录像不再只捕获 P0 模型决策；P0/P1 模型概率、RuleBot 响应及 Core 的移动、召唤、盖放、连锁、攻击、对象关系、指示物、抽卡与 LP 事件均按真实顺序进入回放
- **修复箭头语义与方向**：连锁响应由新发动卡指向上一连锁卡，攻击由攻击者指向目标或对方 LP，卡片移动显示来源区域到目标区域；装备、取对象和多目标选择支持一对多箭头，并为已离场源卡保留幽灵起点
- **可视化动作协议 V2**：选项面板显示 Select/Unselect/Finish/Cancel、选择上下限、当前结果数量、目标卡密/素材值、完成/取消条件及提示字段，能够直接检查 3.5.0 新增的解析信息
- **候选动作交互预览**：点击置信度表中的任意候选，可在棋盘标亮对应发起卡、目标与素材，并在表格上方直接显示相关卡图和协议语义；该预览不会改写录像中的真实选择
- **P1 置信度显示开关**：可隐藏 P1 模型或 RuleBot 的候选置信度表，同时保留其最终决定、棋盘事件和时间轴记录
- **双方完整卡组速览**：新录像在元数据中一次性保存 P0/P1 的卡组名称、主卡组与额外卡组；回放可按玩家和区域查看卡图及同卡数量。该清单仅用于赛后审计，不进入模型观测，旧录像缺少此可选字段时仍可正常播放
- **细化特殊召唤说明**：Type 11 会利用候选卡密和原始区域补回尚未进入实体表的发起卡，明确显示目标卡以及连接、超量、同调、融合或其他特殊召唤入口；Core 只报告结果而没有正规召唤原因时，保守显示“特殊召唤 + 怪兽类别”，避免把墓地复活误写成正规召唤
- **修复播放控制状态**：上下步按钮与时间轴使用同一游标；切换录像立即停止自动播放并回到第 0 帧，单帧录像不再创建非法范围滑块
- **独立回放格式**：新增 `REPLAY_FORMAT_VERSION = 2`。完整场面写入去重状态表，时间轴仅引用 `state_id`，并使用紧凑 JSON，避免异常长局逐帧复制棋盘；实测 574 帧双边录像约 1.09 MB。界面仍可读取旧版帧内状态录像
- 回放区改用 Streamlit 新 `width="stretch"` 接口，消除 `use_container_width` 的弃用警告

### 🧩 Core 与竞技场修复

- **修复 Type 16 字节错位**：恢复项目内置 Core 的 `spe_count + 全局 forced + hint_timing[2]` 头部，并正确跳过第二个候选起的定界字节；Standard Core 使用无定界符布局，取消连锁仅在全局 forced 为 0 时提供
- **修复支付 LP 状态遗漏**：`MSG_PAY_LPCOST`（Type 100）现在同步扣减 DuelState 的 P0/P1 LP，模型观测与回放不会在支付代价后继续保留旧 LP
- 连锁栈保存 Core 原始连锁序号，回放和调试信息不再只能显示未知序号
- **补充防循环诊断**：软禁用覆盖全部候选时同时打印 MsgType、动作说明和各自重复次数。实测警告来自模型在 Type 26 的 Select/Unselect 状态间真实往返，而不是动作状态键合并
- **修复竞技场软禁用失效**：全部候选都达到重复阈值后，不再永久关闭该状态的防循环；仅在异常循环状态中改选访问次数最低的合法候选，使 Cancel、Select、Unselect 与 Finish 都有机会被尝试，正常状态仍保持模型贪心决策
- **补齐训练取消往返反馈**：训练的完整状态访问计数不再于 A→B→A 切换时清空；同一完整局势下前四次 Cancel/Unselect 不受影响，从第 5 次起施加既有量级的 `-0.005` 步奖励，一般动作仍保持第 10 次阈值。训练继续随机采样且不屏蔽合法 Cancel，因此不会破坏正常撤回或 PPO 行为策略
- **进一步放宽长盘塑形**：根据 50 轮训练仍能正常收敛的实测结果，微量回合惩罚从第 40 回合后才开始；1500 步硬截断、50 回合慢胜 `0.05` 与单回合 300 决策阈值保持不变，重点只约束极端长局

### 🖥️ WebUI 稳定性修复

- **修复 TensorBoard 无法启动**：WebUI 改用当前 `python_env` 的 `sys.executable -m tensorboard.main` 和绝对日志路径，不再依赖系统 `PATH` 中是否存在 `tensorboard.exe`；启动失败会留在界面内提示，不再抛出整页 traceback

### ✅ 验证与兼容性

## [v3.5.0] - 2026-09-02

### 🧩 模型动作协议 V2

- **统一动作语义**：`GameAction` 正式记录操作类型、响应值、原始位置、选择上下限、当前结果数量、完成/取消条件、提示字段、宏目标卡密与素材数值；不再依赖模型看不到的 `index`、调试文字或原始响应字节表达关键含义
- **重构动作头输入**：新增操作、响应、完整语义签名、约束上下文、目标代码/数值以及行动方视角位置编码；超过 5 个显式目标槽的剩余组合仍由稳定 32 位语义签名区分
- **修复确定性不可学习选项**：Type 12/13 的 Yes/No、Type 14 的选项描述、Type 19 的四种表示形式与目标卡密现在具有不同模型特征；Type 10 的直接攻击标志和候选卡密也不再丢失
- **补齐 Type 11 洗牌命令**：解析 `can_shuffle` 并生成 Core 规定的 action type 8 响应，避免合法操作永久缺席候选池

### 🔁 顺序选择与组合合法性

- **Type 26 改用原生顺序决策**：每次 Select/Unselect 都编码操作后的完整已选集合、候选卡密/位置、min/max、finishable/cancelable；Finish/Cancel 为独立语义动作。模型逐步与 Core 交互，每一步均写入 PPO 轨迹，并由同局终局奖励通过 GAE 回传，不需要 RuleBot 代选或 MCTS 才能完成动作
- **保留静态宏动作边界**：Type 15/18/20/22/23/24/25 继续由合法性枚举器生成可直接提交的完整响应；候选现在携带目标卡密、顺序、祭品值、星级双值和指示物分配，使不同合法套餐不再在动作头中折叠
- **修复 Type 20 祭品合法性**：按 Core 规则校验“选中张数不超过 max 且 `release_param` 总和不少于 min”，支持单张双祭品值卡，并排除仅张数满足但祭品值不足的无效组合
- **修复 Type 140/141 多项宣言**：当 Core 要求选择多个种族/属性时，组合池一次返回恰好 `count` 个 bit 的 OR 掩码，不再把单个 bit 当作完整响应导致 Retry
- **控制组合池规模**：非场上同名同参数卡按等价副本数量生成规范组合，保留 5000 项合法枚举上限、120 项加权随机候选和最低探索权重，不改变既有随机性
