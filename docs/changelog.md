## [v3.4.2] - 2026-08-31

### 🐛 训练热修复

- **修复采集后垃圾回收崩溃**：移除 `collect_rollouts()` 内部重复的 `import gc`，避免它遮蔽模块级依赖并导致 Worker 完成后首次调用 `gc.collect()` 抛出 `UnboundLocalError`
- 该错误发生在轨迹合并和 PPO 更新之前，不会写入残缺优化器状态或污染既有模型；修复仅恢复原有垃圾回收调用，不改变采样与学习逻辑
- **修复跨轮提交内存阶梯式下降**：主进程轨迹合并池由“每轮销毁并重新申请”改为覆盖有效前缀的跨轮复用，仅在启动预检余量不足时安全释放旧池并复检，最终由 Trainer 关闭流程统一回收
- **增加分阶段内存审计**：记录 Worker 启动、回收、轨迹合并和 PPO 更新后的系统提交量、Trainer 私有提交/RSS、合并池与 CUDA 占用；Worker 记录对手后端初始化后的进程占用，用于核实 hist/ONNX 是单轮峰值而非主进程累积泄漏
- PPO 更新后显式清空最后一批梯度引用；不改变采样分布、奖励、GAE、有效样本边界或参数更新结果

### 📦 一键环境与发布打包

- **补齐 GPU 运行环境**：将便携环境中的 CPU-only Torch 更换为已通过实机 CUDA 张量探针的 `PyTorch 2.9.1+cu130`，恢复 WebUI 与 CLI 从 `python_env` 启动时的 CUDA 训练能力
- **区分启动与发布要求**：普通一键启动允许无 NVIDIA 显卡的电脑按 `auto` 回落 CPU；发布打包默认要求内置 CUDA 环境实际可执行，避免再次生成只能 CPU 训练的误标整合包
- **新增一键打包工具**：`构建一键包.bat` 调用 `build_portable_package.py` 完成环境预检，并将源码、`python_env`、`cards.cdb`、`script` 与 `decks` 打包为 `Galatea_Core_Vx.x.x.zip`
- **兼容边界**：当前 CUDA Wheel 面向现代 NVIDIA 架构，适用于 RTX 20/30/40/50 系及 GTX 16 系；GTX 10 系和更早显卡需要旧版 PyTorch 环境，否则框架会回落 CPU
- 框架显示版本、中英文文档、README 徽章与 `version.txt` 更新为 `3.4.2`；完整测试集 98 项通过

## [v3.4.1] - 2026-08-31

### 🛡️ Windows 采集稳定性与内存优化

- **定位 WinSock 10055 根因**：确认 `No buffer space available` 与 libzmq 原生断言并非 Rule 保底局和 hist 对手冲突，而是多 Worker、大型轨迹池及重复模型副本共同耗尽 Windows Commit Limit 后引发的连锁故障
- **轻量 Worker 推理前端**：当前策略与 self 对手在 Worker 内仅保留特征编码和动作封包能力，不再创建从未执行本地前向的完整 PyTorch 网络；中央推理请求、对手权重和采样分布保持不变
- **移除冗余临时权重**：取消每轮 `tmp_weights_iter_*.pt` 的生成、读取和清理，消除 self Worker 的重复权重副本及无意义磁盘 I/O；正式 PTH 检查点协议不受影响
- **ONNX 优先历史推理**：hist Worker 先校验并挂载带模型 UUID、前缀和轮次身份的 ONNX 产物；仅在 ONNX 缺失、加载失败或运行异常时按需加载正式 PTH 回退网络，避免正常路径同时常驻两套历史模型
- **安全回退与资源释放**：ONNX 运行失败后只切换该 Worker 的历史对手推理后端，当前异常局仍按既有规则回滚；ZMQ 上下文延迟至大型轨迹池分配完成后创建，并统一处理部分初始化失败时的释放
- **Windows 提交内存预检**：每轮唤醒 Worker 前读取系统提交量和提交上限，按轨迹池、Worker 基础空间及 Trainer 安全余量估算需求；资源不足时在创建子进程前明确报错并安全停止，避免演变为 PyTorch OOM、WinSock 10055 或 libzmq 断言
- **回归验证**：覆盖无网络 Worker、ONNX 优先与 PTH 延迟回退、提交内存估算及临时权重移除；完整测试集 87 项通过

### 📚 版本与文档

- 更新中英文功能说明、架构说明及更新日志，补充轻量 Worker、历史模型回退和 Windows Commit Limit 保护机制

## [v3.4.0] - 2026-08-31

### 🧠 中央推理架构重构

- **固定启用中央批量推理**：移除已经失去实际意义的异步推理开关，当前策略与 self 对手统一通过 ZMQ ROUTER、共享内存槽和请求完成号使用同一个中央推理服务
- **Worker 固定使用 CPU**：采集 Worker 不再接收伪设备选项，也不会创建 CUDA 上下文；当前策略与 self 对手均由中央服务推理
- **真实 CPU/CUDA 训练模式**：原设备选项统一为 `--device auto|cpu|cuda`，同时控制中央推理和 PPO 更新设备；`auto` 优先 CUDA，无可用 CUDA 时回落 CPU
- **按设备分离优化路径**：CUDA 保留 pinned memory、非阻塞搬运、TF32、BF16/FP16 与可选 `torch.compile`；CPU 使用普通内存、FP32 和分阶段线程预算
- **联盟 self/hist 分流修正**：新训练的 self 对手直接使用本轮策略权重，不再把内部临时 `.pt` 文件送入正式 `.pth` 检查点加载器；hist 对手继续使用带 UUID 鉴权的正式检查点

### 📚 接口与文档

- CLI 与 WebUI 同步移除旧 `async_infer`/Worker 设备开关，训练设备统一为 `auto`、`cpu`、`cuda`
- 更新中英文 README、快速开始、功能说明、架构设计与特殊处理文档
- 框架显示版本与 `version.txt` 更新为 `3.4.0`

## [v3.2.0] - 2026-05

### ✨ 重大架构升级

- **🧬 FiLM 全局状态调制**：新增 FiLM Generator，根据当前阶段/回合/LP 等全局信号动态生成 Transformer 各层的缩放(γ)与偏移(β)参数，让网络在不同游戏阶段拥有不同的推理倾向
- **🔀 SwiGLU 门控前馈网络**：将传统 MLP (Linear→ReLU→Linear) 全面替换为 SwiGLU 门控线性单元，采用无偏置设计与 Tensor Core 64 对齐优化，显著提升非线性建模能力
- **⚡ ZMQ 零拷贝进程通信**：使用 ZeroMQ ROUTER 微批处理架构替换原有管道通信，结合锁页内存(pinned memory)的极速 DMA 异步搬运，采集时间减半
- **📦 ONNX 推理加速**：新增 `--use_onnx` 选项，训练时自动同步导出 ONNX 计算图，Worker 端使用 ONNX Runtime 进行极速推理，大幅加速数据采集

### 🔧 功能增强

- **🧵 Worker 线程自适应**：根据系统 CPU/内存实时状态动态调整 Worker 行为
- **🔗 连锁堆栈学习**：将连锁堆栈的历史次序与语义信息纳入训练（chain_pos_embed + 连锁语义槽位），AI 能真正理解连锁逆序结算
- **📍 位置排序学习**：修复了行动选择中卡片位置排序未被纳入学习的问题，现在 #25 排序操作会利用加权位置嵌入

### 🔧 优化

- **⏱️ Worker 耗时审计报告**：新增详细的 Worker 各环节耗时统计（推理/编码/通信等），终端实时输出性能瓶颈诊断
- **📡 读写错峰优化**：数据采集与存储阶段错峰调度，避免 I/O 拥堵导致的帧丢失
- **📚 语义库单次注入**：知识库数据仅首次加载时注入，后续迭代直接复用缓存，减少内存抖动
- 其他底层稳定性与细节优化

### 📦 新增依赖

- `pyzmq` - ZeroMQ 进程通信
- `onnxruntime`  - ONNX 推理加速
