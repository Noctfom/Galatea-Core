## [v3.10.0] - 2026-09-21

### 🃏 V4 阶段 4 批次 1：卡组协议边界与 BO3 上层预留

- **完整构筑与单局画像分层**：新增 `deck_protocol.py`。`DeckSpec` 保存主卡组、额外卡组和 Side Deck；`DeckProfile` 只保存主/额外，并从数据类型和序列化载荷上排除 Side，成为当前 BO1 策略的唯一卡组画像边界
- **稳定内容身份**：完整构筑 `deck_id` 与单局 `profile_id` 均按分区、精确卡密和投入数量计算，不受 `.ydk` 卡片排列、文件名或显示名称影响，为后续 Worker 每局登记和画像去重提供稳定键
- **初始/剩余状态解耦**：`DuelState` 新增一局内不可变的初始主/额外卡组副本，原有 `p0/p1_deck/extra` 继续跟踪 Core 驱动的动态剩余卡；`GameSnapshot` 同时携带两类数据，避免后续把已抽取/已召唤卡误认为初始构筑中不存在
- **Side 资源闭环但不进入策略**：`.ydk` 的 `!side`/`#side` 现会被读取，未知 Side 卡单独记录；主/额外合法而仅 Side 不完整的卡组仍可用于当前 BO1 训练与竞技场。WebUI 预检单独展示 Side 警告，不把它误算为 BO1 不兼容
- **BO3/组卡接口预留**：新增位于 `DuelState` 外部的 `MatchContext` 与 `DuelSummary`。其 `policy_inputs()` 当前固定为空，不向单局观测、网络、ONNX 或 PPO 轨迹注入比分、换备或 Side 信息
- **兼容与版本边界**：框架升至 3.10.0；Model Protocol 保持 4、Checkpoint Format 保持 3、V4 结构修订保持 8。本批只建立资源/状态协议和稳定画像来源，不改变网络输入、权重形状、奖励或对局动作逻辑
- **验证**：新增构筑身份置换不变、Side 隔离、Side-only 兼容、分区投入数量及 `DuelState.reset()` 初始画像恢复测试；默认完整回归 212 项中 211 项通过、1 项真实 Core 门控跳过，显式启用后真实 Core 对局通过且查询零解析错误

## [v3.9.2] - 2026-09-21

### 📦 V4 阶段 3 批次 3：静态语义运行资产与跨机器 ONNX/GKG 闭环

- **独立编译运行资产**：新增派生文件 `semantic_lookup_v1.npz` 与 `semantic_lookup_v1.json`。前者以 `allow_pickle=False` 可校验数组保存模型侧结构表和共享代码向量，后者保存精确词表身份、逻辑语义哈希、数组摘要、有效效果槽及完整 `desc → Lua 槽` 目录；两者可由语义源三件套确定性重建，不提交 Git
- **动态更新无陈旧缓存**：远程语义同步、本地 Lua 提取、代码向量生成和权威卡片词表追加都会主动删除旧编译资产；语义管理流程结束时立即重建。手工启动训练、竞技场或一键包构建时若资产缺失，也会在建网前一次性补建，不在对局中生成或读取
- **修复 spawn Worker 效果槽退化**：3.9.1 删除 Encoder 语义库后，Windows spawn Worker 可能没有继承主进程的运行时效果绑定，导致连锁/历史效果槽回退未知。现在 Encoder 仅登记约 0.6 MiB 磁盘目录，不重载 53.47 MiB 数值表；本机 `tracemalloc` 约保留 6.8 MiB Python 目录内存，仍比完整表少约 46.7 MiB/Worker
- **PTH 与 ONNX 分工明确**：训练/PTH 在建网时加载一次 NPZ 并注册为非参数缓冲；ONNX 导出把同一静态表固化到 `.onnx.data`，运行时不依赖 NPZ/JSON，也不暴露任何 `sem_*` 输入。本批外置 ONNX 实测只保留 57 个紧凑输入，ONNX Runtime 输出形状和 PyTorch 路径一致
- **GKG 部署包格式 V4**：`.gkg` 强制携带 `card_vocab.json` 与编译运行资产，对文件摘要、数组 dtype/形状、逻辑语义、模型 UUID/轮次及 ONNX 外置数据进行跨机器复核；`knowledge_base.json + code_embeddings.npy + code_embeddings_idx.json` 改为可选的接续维护源，三者仍不可拆分。WebUI/CLI 导入会自动安装运行表，本机词表更新时拒绝旧包语义源倒灌
- **空间和启动开销**：当前资产的源编译五次均值约 0.528 秒，含源摘要复核的物化表恢复均值约 0.140 秒，启动阶段约快 3.8 倍；独立运行资产展开约 54.06 MiB，相比含 Hash 的维护源约 66.49 MiB 小 18.7%。当前数据的纯运行 GKG 约 1.54 MiB，附带维护源约 3.93 MiB；实际模型包仍主要由 PTH/ONNX 权重决定。本地同时保留源和可重建缓存会额外占约 54.06 MiB
- **热路径保持不变**：没有新增逐步 I/O、Core 查询、网络参数或 PPO 目标；3.9.1 每步净减 152,996 字节、32,768 步约减 4.67 GiB 的轨迹收益完整保留。框架升至 3.9.2，Model Protocol 维持 4、Checkpoint Format 维持 3、V4 结构修订维持 8，既有 3.9.1 检查点无需因部署资产格式变化失效；GKG 格式独立升至 4
- **验收结果**：默认完整回归 208 项中 207 项通过、1 项真实 Core 门控跳过；显式真实 Core 决策闭环通过。另行完成外置 `.onnx.data` 导出、身份标记、文件枚举、CPU ONNX Runtime 推理和无 `sem_*` 输入验证

## [v3.9.1] - 2026-09-21

### 🧠 V4 阶段 3 批次 2：模型侧语义查表与轨迹去重

- **观测内容无损切换**：场面与卡组继续使用既有 `card_idx/deck_idx`；连锁新增 `c_effect_slot`，最近历史新增 `h_card_idx/h_effect_slot`。1～8 指向精确 Lua 效果槽，0 表示绑定未知并保持原来的整卡语义回退，不改变隐藏信息遮罩、公开关系、动作候选或 Core 回包
- **模型侧统一查表**：`GalateaNet` 将 3.9.0 编译的结构语义表注册为非参数缓冲，在当前计算设备上按卡片 token 与效果槽还原原有九组语义张量；这些缓冲不进入可训练参数或检查点权重，不影响梯度和 PPO 目标
- **删除逐步重复矩阵**：Encoder 不再加载/编译语义库，也不再生成 `sem_* / d_sem_* / c_sem_* / h_sem_*`；Trainer 的共享内存、锁页聚合区、Worker 轨迹和 PPO 合并池同步移除这些字段。中央推理 Worker 因此不再各自常驻约 53.47 MiB 静态语义资产
- **内存收益**：旧展开字段每步占 153,080 字节，新补身份字段共 84 字节，净减少 152,996 字节（约 149.4 KiB/步）；32,768 步的单份轨迹池约减少 4.67 GiB。默认 512 PPO mini-batch 也由重复语义约 74.75 MiB 降为一次常驻约 12.97 MiB 结构表
- **性能边界**：设备内查表存在固定索引开销；本机 RTX 5070 Ti、512/8/6、单样本基准中纯前向约增加 1.59 ms，但省去 CPU→CUDA 展开矩阵搬运后总耗时由约 13.11 ms 降至 12.16 ms。实际批量与异步流水会变化，因此该数据只作方向性基准；不存在额外 Lua/CDB 查询或逐步磁盘 I/O
- **逐元素等价门禁**：保留一条仅供测试使用的旧展开输入支路，同一权重下对紧凑与展开观测执行完整网络前向，`logits/value/v_input` 达到 `rtol=0, atol=0`；ONNX Runtime 同步验证紧凑输入，导出签名不再包含任一展开 `sem_*` 字段
- **结构边界**：框架版本升至 3.9.1，Model Protocol 保持 4、Checkpoint Format 保持 3，V4 结构修订升至 8。网络可训练参数形状未变，但结构修订 7 的开发制品仍按 V4 从零训练策略拒绝混用
- **回归结果**：默认完整回归共 207 项（206 项通过、1 项真实 Core 环境门控跳过）；显式开启后的真实公开 Core 决策闭环通过，ONNX/PyTorch 输出继续保持既有容差

## [v3.9.0] - 2026-09-21

### 🧠 V4 阶段 3 批次 1：模型侧静态语义表与资产身份

- **统一静态语义编译**：新增 `semantic_lookup.py`，把结构语义、条件、关联卡、代码向量索引和有效效果槽一次性编译为按 `card_vocab.json` 精确 token 与 Lua 效果槽对齐的稠密表；卡密仍以真实编号查询，不使用卡面效果序号或取模 Hash
- **兼容桥接不改决策输入**：现有 Encoder 暂时通过 `SemanticKnowledgeBase` 兼容接口读取统一查表，字段形状、数值编号、动作协议、网络参数、奖励与 PPO 流程均未改变；真正删除轨迹内重复语义张量留在 3.9.1
- **消除进程内重复资产**：Encoder 和 `GalateaNet` 共用同一份代码向量及结构语义缓存，移除旧知识库初始化的随机等待和网络层独立 `.npy` 副本；语义三件套缺失或错位时继续严格拒绝启动，不再以全零语义静默运行
- **语义前缀身份**：新增 `semantic_lookup_format_version / semantic_lookup_hash / semantic_lookup_card_count`。哈希按实际卡片 token、效果槽、结构字段及其逻辑代码向量计算，不依赖 `.npy` 的物理行号；只追加新卡及其语义时旧模型前缀仍可验证，修改旧卡任一静态语义会在建网前拒绝
- **产物身份闭环**：新语义身份已写入 PTH 顶层与 `net_config`、ONNX 元数据、轮次制品清单和 `.gkg` 清单。部署包创建与解包校验会对其实际携带的语义资产重新编译前缀哈希，形状仍合法但内容被替换的向量也无法通过
- **在线更新缓存失效**：查表缓存同时观察知识库、代码向量和索引的文件时间/大小签名；资源同步或本地接续更新后，新建 Encoder 会自动切换到新表，不沿用常驻 WebUI 进程中的旧语义
- **资源基准**：当前 14,981 卡词表与 27,647 个效果槽编译耗时约 0.35 秒；结构表约 12.97 MiB、共享代码向量约 40.50 MiB，合计约 53.47 MiB。旧实现仅两份代码向量就约 81 MiB，尚未计入逐卡 Python 缓存；10 万次单卡查表约 0.095 秒
- **结构身份边界**：框架版本升至 3.9.0；Model Protocol 保持 4，Checkpoint Format 保持 3，V4 结构修订升至 7。结构修订 6 的开发检查点缺少静态语义身份，按 V4 从零训练约定明确拒绝而不迁移
- **回归范围**：新增精确 token/效果槽对齐、语义前缀追加、向量物理换行等价、旧卡向量篡改和部署包篡改测试；完整回归共 206 项（205 项通过、1 项按环境门控跳过），另行显式启用的真实 Core 决策闭环也已通过。自动回归同时覆盖 ONNX 导出/运行时一致性；本批不删除共享内存/轨迹里的旧语义矩阵，也不改变 ONNX 网络输入，作为 3.9.1 切换前的独立审查点

## [v3.8.2] - 2026-09-20

### 🔗 V4 阶段 2 批次 3：公开卡片关系与 Core 状态闭环

- **只依赖公开 Core**：新增独立旧式 `query_card` 解析器，覆盖公开标准字段并使用 `query_field_count` 校准手牌、墓地和除外区；没有修改 `ocgcore.dll/.so`，也没有引入 Galatea 私有内核分支
- **修复真实查询回包崩溃**：旧式 Core 将查询结果写入 `ctypes.c_byte` 缓冲；原实现把含负值的 Python 列表直接传给 `bytes()`，遇到任意 `0x80` 以上字节便反复报 `bytes must be in range(0, 256)`。现按原始内存无符号复制，并让真实 Core 门禁强制断言查询成功且零解析错误，禁止再由消息镜像回退掩盖故障
- **补全动态个体状态**：模型现可接收动态卡名、等级/阶级、当前与基础攻防、灵摆刻度、连接值/箭头、原因位、原持有者及 `STATUS_DISABLED / STATUS_PROC_COMPLETE / STATUS_FORBIDDEN`；0 星不会再被静态阶级或连接值错误回填
- **补全公开关系**：装备源—目标、效果取对象、原因卡与装备反向关系均映射到实体索引；超量素材从“只看第一张”扩展为最多 16 张精确身份，指示物从总数扩展为 8 组类型—数量
- **正规出场认知**：`STATUS_PROC_COMPLETE` 随卡片查询结果进入场上、墓地和除外实体，可用于学习苏生限制；精确召唤方式、来源与玩家仍未由公开查询 API 导出，因此保持未知，不通过卡类、区域或消息顺序猜测
- **遵守公共内核边界**：核查上游 v11.0 后确认规则脚本可在 Core 内部读取召唤信息，但客户端标准查询仍没有相应字段。该能力列为上游 API/PR 待办；未来升级按公开 `OCG_DuelQuery` ABI 整体适配，不在本地二进制增加私有字段
- **修复宏动作错误等价**：场上、墓地和除外区的同名卡始终保留物理个体；隐藏/重置区仅在卡密、提示参数与已知状态完全一致时折叠，既避免把不同正规出场/关系状态的卡误当成同一项，也保留原有 5,000 组合上限和加权缩减
- **补齐公开位置与关系消息**：支持 `FIELD_DISABLED`、`UNEQUIP`、`CARD_TARGET/CANCEL_TARGET` 镜像，识别 Core 的 `POS_REVEAL` 公开位；消息白名单补入 Type 95/161/162
- **消息覆盖审计**：审计报告结构升至 3，逐消息区分 `decision_parsed`、`state_applied`、`query_reconciled` 与 `known_observation_gap`；WebUI 直接显示罕见待补消息，不让未消费的公开信息静默存在
- **收口动作消息残留**：补通 Type 21 连锁排序的解析、RuleBot、宏池、Worker、竞技场和模型双阶段链路；Type 22 指示物分配新增 Pass1 卡片/可用数量语义。硬币、骰子和猜拳结果不再被 Worker、竞技场或 RuleBot 自检误当成等待回复的决策消息，避免错误清空同批后续消息
- **修复自检误导信息**：空闲阶段 Type 0/2/4 等六类候选补齐可读操作名；全息质检按独立 `rank`/`link_rating` 显示超量阶级和连接值，不再沿用旧 V2 的复用 `level` 说明
- **封闭记牌器透视路径**：已公开卡片进入对手隐藏区后仍可保留其身份和静态卡片知识，但不再复用 Core 查询所得的隐藏动态攻防、类型、关系、素材、指示物或状态
- **已知剩余边界**：精确召唤来源等待上游公开接口；Type 35/38/120/160/161/162/165 等换墓、顶卡/提示或非标准模式消息先由审计留样，不作为普通 BO1 的伪造观测
- **紧凑轨迹存储**：原因位、指示物类型与禁用区域使用小端字节无损打包，卡片词表索引使用有界 `int16`，关系索引使用 `uint8`；基线每步新增约 13.1 KiB，32,768 步约 420 MiB 轨迹数据，避免直接逐位展开造成更大内存增长
- **结构身份边界**：框架版本升至 3.8.2；Model Protocol 保持 4，Checkpoint Format 保持 3，V4 结构修订升至 6。新增网络输入和参数会使修订 5 检查点在建网前明确拒绝
- **回归验证**：便携 Python UTF-8 环境默认运行 200 项测试，199 项通过、1 项真实 Core 门控用例按预期跳过；门控用例单独启用后完成真实 Core 对局，并确认 `query_card` 成功次数大于 0、解析错误为 0。覆盖完整公开查询报文、Type 21/22 动作链、截断拒绝、隐藏信息遮罩、关系/状态编码、墓地同名卡保留、共享内存、PyTorch/ONNXRuntime 数值对齐与实际 Core 回包

## [v3.8.1] - 2026-09-20

### 🧩 V4 阶段 2 批次 2：选择状态机与响应闭环

- **保留 Core 原生边界**：Type 26 继续逐项 Select/Unselect；Type 15 普通多选、Type 20 解放选择和 Type 23 凑星/凑值一次返回完整合法组合，不引入虚拟中间状态
- **补齐素材意图输入**：Type 20/23 现在为每张候选生成 Pass1 动作，显式携带解放值、单值/双值参数、目标总值、必选数量和 Exact/SumGreater 模式；模型偏好能够实际参与组合池加权缩减
- **逐消息复刻 Core 校验**：新增统一选择协议校验器，覆盖索引范围、重复索引、张数上下限、解放值总和、必选占位、双值求和、Type 26 单索引响应，以及取消/完成许可
- **修复 Type 23 伪取消**：`MSG_SELECT_SUM` 没有取消标志，旧候选池无条件加入 `int32(-1)` 会必然触发 `MSG_RETRY`；现已删除并在入池/发包时双重拒绝
- **修复 Type 26 错误回包类型**：逐项动作过去因 `response_value` 提前返回整数，可能误走 `set_responsei`；现在普通 Select/Unselect 固定返回 `count=1 + index` 字节，只有 Finish/Cancel 使用 `int32(-1)`
- **保留固定形状出口**：Type 26 的 Finish/Cancel 固定置于候选池首位；Type 15/20 的真实取消组合在宏动作缩减时固定保留，不会因候选超过 120 被采样丢失
