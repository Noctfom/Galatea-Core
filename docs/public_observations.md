# 公开观测、询问与连锁上下文

> 当前使用说明适用于 v3.16.9；历史小节保留各功能引入时的合同与测量记录

## 3.16.9 当前询问与连锁上下文

模型输入增加独立的当前上下文：**108项变为116项，结构修订14变为15**。Model Protocol仍为4、Checkpoint Format仍为3，512/8/6等主干配置与全部已有参数名称、形状保持不变。当前事实与16条已完成动作事件分开，不伪造动作、奖励或辅助监督，不增加PPO学习行。

| 来源 | 新增可见事实 | 生命周期与未知状态 |
| --- | --- | --- |
| Type2 / SELECTMSG(3) | 当前选择提示的完整32位参数、提示类型和接收方 | 决策前可见；15/18/20/23/24完成后消费；26连续选择保留，结束或离开流程后消费；Retry保留；新提示替换旧提示 |
| Type2其他已知子类型 | 接收到的事件说明、选项/宣言公告、卡名/区域提示原值 | 按实际接收方脱敏；链内保存到链结束，无链通知每视角保留最近16项；不把显示文字编号一律当作效果槽 |
| 70/71 | 原始链号、已建立/已确认状态 | 不弹栈重编号，整个连锁保留到74 |
| 72/73 | 哪条链开始处理、哪条已处理 | 73后保留最近处理链号，同时明确已处理；后续72切换，74清空 |
| 75/76 | 指定链的发动无效/效果无效 | 两类状态分别保存，不把聚合的“发生过无效”当作全部链无效 |
| 83 | 公开指示对象、公告时位置、已知卡密、当前可追踪位置 | 随可证明的移动/交换更新；洗牌或身份不可证明时失联，保留原公告，不绑定旧槽位的新卡 |
| 162 | 恢复后的链来源 | 报文未携带的处理状态、对象和选择用途标为未知，不沿用重载前缓存 |

SELECTMSG的参数不一定是“代价/目标”等用途编号：例如放置提示也可使用卡密。MSG83也可由`Duel.HintSelection`产生，所以本合同称“公开指示对象”，不宣称它必然是规则上的取对象关系。当前目标独立于查询得到的`QUERY_TARGET_CARD`持久关系。

无链情况下，Core可以逐张发送同一次指示的MSG83，接收端会累积而不是只保留最后一张。这些对象保留到接下来的决策，Retry沿用同一窗口；下一次新决策或终局、回合、阶段切换会清理旧公告。重复局面签名也包含询问和连锁上下文，避免将用途已变化的选择误认成同一循环。

Type2的玩家字段是原始投递字段，不是通用行动者：1/2/3/5送给该玩家，4/6/7/8/9送给另一玩家，10/11双方接收。受控WindBot桥同步修正4的接收方和11的广播，依据[上游客户端投递逻辑](https://github.com/Fluorohydride/ygopro/blob/master/gframe/single_duel.cpp#L593)。未知提示子类型不构造模型事实，也不单凭该类型中断合法对局。

### 输入与网络路径

`public_observation.CURRENT_CONTEXT_INPUT_SPECS`定义八个`current_context_*`字段，共256项事实容量：`mask`、`kind`、`code`、`location`、`chain`、`offset`、`subtype`、`value`。编号以完整四字节表示，玩家采用相对角色；卡密按该视角已知信息遮蔽。容量不足明确报错，不静默截掉对象或替换历史。

`PublicContextEncoder.encode_current_context`复用已有公开通知的类别、位置、数值、池化、投影和门控参数。按链号分别汇聚后，链事实加到对应链表示；询问及无链事实加到全局公开上下文，最终进入共享状态、策略、价值和规划。既有链雷达仍是12条，超出12的新增事实保留原链号并进入全局组。没有扩大120卡主干序列，也没有增加可学习参数。

空上下文与旧网络输出逐位一致；有效新增事实会改变输出。旧通知门控保留原值，新增类型可能尚未学好，继续训练会共同调整这些共享参数。不能将“权重完整继承”理解成“更新后行为完全不变”或“无需再学习”。

新增存储为每样本5,120字节，32,768样本约160MiB；Worker预分配与主合并池分别计入。5070Ti、512宽、FP16下仅测新增分支：batch12 CUDA Graph前向约0.132ms、峰值额外7.65MiB；batch512前向加反向约12.91ms、峰值额外332.88MiB。此为分支量级，不是完整训练的增幅或长训显存保证。

### 接续、导出与录像

- 已知完整修订14合同的PTH可迁移到15，保留全部权重；常规PPO恢复继续保留Adam、AMP、轮次和模型身份。BC初始化新PPO分支仍遵循原有独立优化器规则
- 原PTH在普通加载时不改写；下次保存记录当前合同和`observation_protocol_updates`来源。词表编号、语义编码器和未知结构差异仍校验，未开放任意版本混用
- 主进程与Worker同步重启，使用新一轮采集；不把旧已编码样本和旧log-prob混进新观测PPO更新
- 旧ONNX的静态图没有此路径，需在现有“资源同步→ONNX检查与更新”入口由同名PTH重导出；不重建语义向量、词表或哈希分类。只有旧ONNX时无法靠修改元数据补入新计算路径
- 旧规范轨迹/BC缓存继续按原合同严格核验；重建当前观测需要完整原始消息、查询及响应证据，不能只换摘要。本批不提供旧规范轨迹的自动迁移。旧全息JSON仍可查看，但不会补造当时未保存的事实
- 新全息记录保存`prompt_context`、逐链状态/目标、`resolving_chain_index`及无链指示对象；Core受控入口、训练、竞技和离线重放共用状态实现。Link模型读取器需同步八个新字段及修订15，原真实服务器观测门禁不会因此自动放行

本批不改变奖励、温度、GAE、KL门槛、DeckFiLM强度或辅助任务目标。是否交康、是否自破坏仍由经验学习，新增输入只减少不同真实局面被编码成相同观测的情况。

## 状态如何维护

| 消息 | 保存的信息 | 生命周期与边界 |
| --- | --- | --- |
| 120 | 错过时点的卡密/位置、结果位、消息顺序、最近处理链序 | 独立通知不覆盖模型动作来源；没有 desc、目标或原因，不能归罪于某个精确效果槽；无额外扣分 |
| 160 类别0 | 清除实例最新数值提示 | 不删除独立维护的说明引用；清除通知仍进入既有事件/回放路径 |
| 160 数值型1～5 | 最新提示类别与完整32位数值 | 不改宿主卡身份、实际属性/种族/指示物；普通移动清理数值提示，同位置表示变化不清理 |
| 160 说明型6/7 | 实例坐标+desc引用计数 | ADD加一、REMOVE减一，零时删除；跟随已知实例移动/连续区域平移/控制权交换/素材层序变化 |
| 165 | 受影响玩家+desc引用计数 | 不绑定场上槽位，也不随16步历史滚动或回合结束自行消失；以实际REMOVE清理 |
| 37/38 | 双方反转状态、合法公开的卡组位置/身份/表侧标志 | 37映射双方已知位置；38偏移按消费当时数量解释；抽卡/移动平移或失效，洗牌清顺序，不推测隐藏卡 |
| 162 | 固定7怪兽槽/8魔陷槽、表示/素材数、LP、各区数量、连锁 | 严格验证整包后原子重建，再由公开查询补全；未知身份不补成已知，旧提示/近期历史不继承 |

数值提示与说明引用分开维护。手牌洗牌先清旧映射，再接收 Core 重发的说明 ADD，防止引用翻倍。隐藏盖卡重排不能借内部查询偷追实例；无法恢复的提示清除并设置不完整标志。额外/卡组洗牌同样不把无法证明的提示留在旧位置。未匹配 REMOVE 不产生负计数，而是明确标记状态不完整。

### 3.14.1 提示边界热修

Type160 严格保留九字节布局，并允许 Core 的类别0～7。卡片脚本初始化时，公开 Core 可以在卡还未加入区域时发送 `controller=PLAYER_NONE(2), location=0` 的 CLIENT_HINT；例如20989253的初始化过程能够真实复现。控制方0/1的空区域同样没有可见宿主。这些消息按公开客户端语义忽略，不制造P2卡片、不占当前提示/历史通知槽、不标成观测残缺，也不进入全息事件；原始轨迹仍保留实际收到的报文。

已经有合法区域的提示不要求宿主先存在于 Python 查询镜像，以免时序滞后丢信息。类别0仅清数值；6/7引用生命周期保持原样。未知类别、异常控制方、PLAYER_NONE配非空区域及截断/多余字节仍拒绝，报错包含具体位置/类别/数值。这里不是关闭解析校验或启动猜测式效果追踪。

Model Protocol4 / Checkpoint3 / 结构修订14、23个公开输入字段及语义资产身份不变；兼容检查点可以恢复。更新代码后需重启训练/竞技场进程，不会实时替换正在运行的 Worker。

“提示存在”不等于“规则必然生效”。例如念动力防卫者的数值提示不能作为通用失效计时器。`hint_age` 只表示距通知经过多久，不是剩余期限。未使用 CLIENT_HINT 的持续效果（如本地增殖的 G、锁鸟相关效果）仍不能靠此目录精确追踪；没有猜测式补全。

公开客户端的 CARD_QUESTION（谜题）玩家提示会限制收到提示一方的墓地查看，Encoder 只对该视角遮蔽查询身份/动态状态，保留既有合法历史记忆，不向双方统一屏蔽。

## 是否需要新语义表

不新增句向量模型，也不另存一套代码嵌入。`public_hint_semantics.py` 从现有 knowledge_base 的运行时绑定及 raw_code 编译轻量目录：

1. 唯一、已证明的初始化效果绑定标为 `exact`。
2. 回调内创建的提示只能标为 `parent context`，引用已包含该回调代码的父效果语义向量；不能冒充独立精确效果槽。
3. 注释/字符串不参与匹配；动态参数、无法证明来源、歧义绑定保持 `unknown`。原始 desc 仍以四字节保留，不取模合并身份，不猜 `desc & 15`。

提示宿主、受影响玩家、被宣言卡、语义来源和说明参数是不同字段。网络直接选择已知单槽代码行，不为每条提示展开8个效果槽。

Lua解析在源码可用时保存 `public_hint_parent_desc_ids`；清洁远程库保留此元数据仍可复用对应向量。3.13.3审计时的旧库仅613条效果保留源码，无法证明的提示保持未知。3.13.4已完成可信来源提取和代码向量重建，后续本地接续也会维护提示来源；当前绑定以实际资产目录为准，不能把旧库审计数当成现有资产状态，也不能仅凭效果名强配最新脚本。

旧代码向量的异常重复已在3.13.4确认由缺/空源码生成及只按键接续造成，而非Hash粗分类：可信重建后27,647槽有26,092个不同向量，仍有27槽静态来源不完整并明确标记。统计是该次重建证据，不是固定要求；当前资产可在“代码语义质量”或 `semantic-check` 中检查。详见 [来源修复与启用](code_semantics.md)。

目录保存在已有 `semantic_lookup_v1.json`，加入语义逻辑哈希和 GKG 资产身份。旧目录缺少扩展时，若完整源语义资产在本地则自动重编译；仅有旧编译资产的部署必须重新导出/打包，不能凭空生成代码含义。现有本地提取、接续/远程同步和 GKG 打包沿用同一编译入口，不需要重新生成已有代码向量。更新提示目录会影响语义身份，不能和训练时资产偷偷混用。

## 模型、存储与开销

`public_observation.py` 共用23个紧凑字段规格：最多128条当前提示；双方各256个卡组位置；16个历史转移中每项最多8条有序通知。提示/位置输入保存身份、类别、参数、引用数和可见性，不保存展开向量。卡顶从顶端偏移表达，公开位置保留完整8位序号及素材层序。

当前提示超出128条时明确拒绝不完整观测，不静默丢弃；历史通知超过8条保留前8条并设置既有 MESSAGE_OVERFLOW 质量位。它不是“剩余全部效果都不存在”的意思。

`PublicContextEncoder` 使用至多128维的轻量嵌入、池化和有界门控残差。宿主提示在主干之前融合到原120个卡片位置；玩家提示、未绑定宿主提示和已知卡组位置形成动态全局上下文，进入策略、价值及共享规划路径。有序通知进入既有事件编码器。稳定 DeckProfile/卡组风格画像不变，Side 不进入观测。

门控零初始化，对相同公共权重验证了初始化输出逐位一致；之后网络可学习使用新增事实，因此不能承诺训练后的策略与旧模型相同。空池安全归零，卡密/desc不作为大小量值，提示年龄使用对数尺度。没有缓存可训练向量造成梯度过期。

测量边界：本机512/8/6、eager、GPU BF16，比较同一网络启用/绕过新增分支，不是六天长训基准：

- 新增 **8,710字节/步**；32,768步约 **272.19 MiB**观测存储。Worker预分配余量和主合并池也需计算，内存预检已使用新增规格。
- 分支665,472参数；连同辅助头两个扩展输出，总新增665,986参数（约1.26%），全网53,661,973参数。
- CPU单样本约81.99→83.81ms（+2.2%）；CUDA batch6前向约15.23→16.37ms（+7.5%）；CUDA batch128前后向约267.92→279.11ms（+4.2%）。后者峰值已分配显存约增加250.69MiB。
- 空当前提示编码约0.028ms/步。机器、场面、线程和批次会影响测量；不宣称整体训练仅增加这些百分比，也不把它称为零开销。

## 回放与验证

全息回放保存当前公开状态及当时的语义绑定，右侧“公开提示与已知卡组位置”展示引用数、原始参数、Lua来源/槽位/绑定级别、卡顶位置；120、160/165、37/38、162也有独立事件说明。旧全息 JSON 缺少字段时仍能打开，不会给旧录像补造新事实。

验证包括构造截断/拼接报文、引用生命周期、移动/洗牌/反转/抽卡顺序、隐藏信息和双视角、来源不串线、单槽语义/资产哈希、梯度与零门等价、ONNX输入及数值、真实公开Core快照/玩家提示、多局记录与重放，以及小配置CPU中央推理/PPO训练。详见更新日志中的最终测试结果；没有完成生产规模长训。

保留边界：**Type35整片墓地/卡组交换暂不适配**，Type161 Tag多人模式也不补全。162不会恢复它没携带的先前提示、隐藏顺序或完整起局历史。上述对局不能宣称观测完整；相关原始轨迹继续带质量门禁。
